# 1. 시작하기

## 1.1 Customer Vault란

Customer Vault는 고객사 정보, 점검서, 구성 정보, 지원 이력, 회의록, 업그레이드 계획을 한곳에서 관리하는 내부 업무 시스템입니다.

## 1.2 권한 안내

| 권한 | 설명 |
|---|---|
| 일반사용자 | 고객사 정보 조회·편집, 점검서 업로드, 지원 목록·회의록·구성 정보 작성 |
| 관리자 | 일반사용자 기능 + 계정 관리, 업무 현황, 서비스 로그, 점검서 삭제, 공지 작성 |
| 슈퍼관리자 | 관리자 기능 + 시스템 설정, 백업 관리, 시스템 이력 |

계정은 관리자가 발급합니다. 계정이 필요하면 관리자에게 요청하세요.

## 1.3 접속 및 로그인

![그림 1-1 로그인 화면](images/user/01-01-login.png)

<!-- 캡처: /login 화면 전체. ① 아이디 ② 패스워드 ③ 로그인 버튼 표시 -->

1. 웹 브라우저에서 안내받은 주소로 접속합니다.
2. **아이디**와 **패스워드**를 입력하고 **로그인**을 누릅니다.

로그인할 때 다음 안내가 나타날 수 있습니다.

| 상황 | 화면 | 해야 할 일 |
|---|---|---|
| 최초 로그인 또는 비밀번호 초기화 후 | 비밀번호 변경 필요 | 새 비밀번호로 변경한 뒤 다시 로그인 (1.4 참고) |
| 비밀번호 사용 기간 만료 | 비밀번호 변경 필요 | 새 비밀번호로 변경 |
| 다른 곳에서 이미 로그인 중 | 중복 로그인 감지 | 계속하면 기존 접속이 로그아웃됨 |
| 2차 인증 적용 대상 | 2차 인증 등록 / 코드 입력 | 1.5 참고 |

## 1.4 비밀번호 변경

![그림 1-2 비밀번호 변경 창](images/user/01-02-change-password.png)

<!-- 캡처: 우측 상단 프로필 → 패스워드 변경 다이얼로그. 비밀번호 요구사항 영역 표시 -->

1. 화면 오른쪽 위의 사용자 이름을 누르고 **패스워드 변경**을 선택합니다.
2. **현재 비밀번호**, **새 비밀번호**, **새 비밀번호 확인**을 입력합니다.
3. 창 아래의 **비밀번호 요구사항**(최소 길이, 대문자·특수문자·숫자 포함 여부)을 모두 만족해야 합니다.
4. **변경**을 누르면 새 비밀번호로 다시 로그인합니다.

> 새 비밀번호는 현재 비밀번호와 달라야 합니다. 최초 로그인·비밀번호 초기화 후에는 이 창을 닫을 수 없습니다.

## 1.5 2차 인증(OTP)

관리자가 2차 인증을 켜고 적용 대상에 포함된 경우에만 사용합니다.

![그림 1-3 2차 인증 등록](images/user/01-03-mfa-setup.png)

<!-- 캡처: 2차 인증 등록 다이얼로그(QR 코드 영역은 흐리게 처리) -->

**처음 등록할 때**

1. 휴대폰에 Google Authenticator 또는 Microsoft Authenticator 앱을 설치합니다.
2. 앱에서 계정 추가를 선택하고 화면의 QR 코드를 스캔합니다. 스캔이 안 되면 화면에 표시된 수동 키를 입력합니다.
3. 앱에 표시된 6자리 코드를 입력하고 **등록 완료**를 누릅니다.

**이후 로그인할 때**

로그인 후 앱에 표시된 6자리 코드를 입력합니다.

> 휴대폰을 바꾸거나 앱을 지운 경우 관리자에게 **OTP 등록 초기화**를 요청하세요.

# 2. 대시보드

![그림 2-1 대시보드](images/user/02-01-dashboard.png)

<!-- 캡처: 일반사용자 계정의 대시보드. ① 내 담당 고객사 점검 현황 ② 담당 고객사 목록 ③ 바로가기 버튼 -->

로그인하면 처음 보이는 화면입니다.

- **내 담당 고객사 점검 현황**: 담당 고객사의 점검 대상, 점검 완료, 미진행 점검, 검증 대기 건수와 점검 완료율
- **담당 고객사 목록**: 각 고객사의 유지보수 정보, 구성 정보, 지원 목록, 회의록, 점검서로 바로 이동
- **검증 대기**: 내가 검증 담당자로 지정된 가상PC 체크리스트·업그레이드 계획 항목

> 담당 고객사가 없으면 "현재 담당 고객사가 없습니다."가 표시됩니다. 담당 지정은 관리자에게 요청하세요.

## 2.1 공지사항 팝업

새 공지가 있으면 로그인 후 팝업으로 표시됩니다. **다시 보지 않기**를 누르면 같은 공지가 다시 뜨지 않습니다.

# 3. 고객사 관리

## 3.1 고객사 목록

![그림 3-1 고객사 목록](images/user/03-01-customers.png)

<!-- 캡처: /customers. ① 검색/필터 ② 고객사 추가 ③ 행별 바로가기 버튼(회의록·점검서·업그레이드 계획·구성 정보·유지보수 정보·지원 목록) ④ 페이지 이동 -->

상단 메뉴의 **고객사 관리**를 누르면 전체 고객사 목록이 표시됩니다.

**검색과 필터**

| 항목 | 값 |
|---|---|
| 고객사명 | 검색어 입력 |
| 버전 | 전체 / 버전별 |
| 점검주기 | 매월, 분기, 반기, 연1회 |
| 점검 상태 | 완료, 미진행, 대상아님 |
| 계약 상태 | 유상, 무상, 만료 |

검색어와 필터는 고객사 관리 화면을 벗어나면 초기화됩니다.

**페이지 유지**

목록 2페이지에서 고객사 화면으로 이동했다가 **목록으로**를 누르거나 브라우저 뒤로 가기를 하면 2페이지로 돌아옵니다. 상단 메뉴의 **고객사 관리**를 누르면 1페이지부터 표시됩니다.

**행별 바로가기**

| 버튼 | 이동 화면 |
|---|---|
| 회의록 | 3.9 회의록 |
| 점검서 | 3.4 점검서 |
| 업그레이드 계획 | 3.6 업그레이드 계획 |
| 구성 정보 | 3.7 구성 정보 |
| 유지보수 정보 | 3.2 고객사 상세 |
| 지원 목록 | 3.8 지원 목록 |

**고객사 추가**

1. **고객사 추가**를 누릅니다.
2. 고객사명을 입력하고 저장합니다.
3. 나머지 정보는 3.3 고객사 정보 수정에서 입력합니다.

**전체 고객사 요약**

전체 고객사의 버전, 점검주기, 계약 기간, 담당자를 한 화면에서 보고 엑셀로 내보낼 수 있습니다.

## 3.2 고객사 상세(유지보수 정보)

![그림 3-2 고객사 상세](images/user/03-02-customer-detail.png)

| 구분 | 항목 |
|---|---|
| 기본 정보 | 고객사명, 위치 |

| 점검 대상 제품 | 유형, 제품명 |

| 담당 | 엔지니어, 부 엔지니어, 영업 담당 |

## 3.3 고객사 정보 수정

![그림 3-3 고객사 정보 수정](images/user/03-03-customer-edit.png)

<!-- 캡처: /customers/:id/edit. ① 점검 대상 제품 추가 ② 저장 -->

1. 고객사 상세 화면에서 **수정**을 누릅니다.
2. 항목을 수정하고 **저장**을 누릅니다.

- **고객사명**은 필수입니다.
- **점검 주기**: 매월, 분기, 반기, 연1회, 협력사진행, 무상기간
- **최근 점검일**은 점검서 업로드 시 자동으로 반영됩니다.
- **계약 시작일**은 최초 계약일로 두고, 갱신 시에는 **계약 종료일**만 변경합니다. 점검 현황의 누락 점검 계산이 이 값을 기준으로 합니다.
- **점검 대상 제품 추가**로 유형·제품명을 등록하면 점검서 업로드 시 점검 대상으로 선택할 수 있습니다.

> 고객사 삭제는 관리자만 할 수 있습니다.

## 3.4 점검서

![그림 3-4 고객사 점검서 목록](images/user/03-04-documents.png)

<!-- 캡처: /customers/:id/documents. ① 점검 항목별 점검서 양식 업로드/다운로드 ② 날짜 필터 ③ 점검서 목록 -->

고객사별로 업로드된 점검서를 확인합니다.

- **날짜 필터**: 시작 날짜~종료 날짜로 기간 검색
- **목록 항목**: 점검서 파일명(또는 미보관 사유), 점검달, 점검자, 점검제품, 점검방식
- **보기**: 점검서를 브라우저에서 열람
- **점검서 양식**: 점검 항목별 양식 파일을 업로드·다운로드 (pdf, doc, docx, hwp, hwpx, ppt, pptx)

## 3.5 점검서 업로드 (일반사용자 전용)

![그림 3-5 점검서 업로드](images/user/03-05-document-upload.png)

<!-- 캡처: 상단 메뉴 점검서 업로드 화면. ① 고객사 ② 점검 대상 ③ 점검 방식 ④ 점검일 ⑤ 미보관 체크 ⑥ 파일 선택 -->

1. 상단 메뉴의 **점검서 업로드**를 누릅니다.
2. **고객사**, **점검 대상**, **점검 방식**(방문 점검/원격 점검), **점검일**(실제 점검한 날)을 선택합니다.
3. 점검서 파일을 선택하고 **업로드**를 누릅니다.

**점검서를 보관하지 않는 경우**

고객사 정책 등으로 점검서 파일이 없으면 **점검서 미보관**을 선택하고 사유를 입력한 뒤 **점검 완료 등록**을 누릅니다.

> 점검 대상이 보이지 않으면 고객사 정보 수정 화면에서 점검 대상 제품을 먼저 추가하세요. 업로드한 파일은 바이러스 검사를 거칩니다.

## 3.6 업그레이드 계획

![그림 3-6 업그레이드 계획](images/user/03-06-upgrade-plan.png)

<!-- 캡처: /customers/:id/upgrade-plan. ① 일정 상태 ② 버전·일정 ③ 공통 고려 사항 ④ 커스텀 항목 ⑤ 진척 현황 -->

메이저 버전 업그레이드 시 고려할 항목과 진행 상황을 관리합니다.

| 영역 | 내용 |
|---|---|
| 업그레이드 일정 상태 | 예정, 미정, 완료 |
| 버전 관리 및 일정 | 현재 버전, 업그레이드 버전, 예상 일정, 검증 담당자 |
| 공통 고려 사항 | 클라이언트·관리서버(관리웹) 항목별 기능, 설명, 검토, 검증, 비고 |
| 고객사별 커스텀 항목 | 공통 항목에 해당하지 않는 이 고객사만의 고려 사항 |
| 진척 현황 | 날짜·작성자·내용 기록 (본인 작성분만 수정·삭제 가능) |

**수정 방법**

1. **수정**을 누르고 항목을 입력합니다. **기본 양식 사용하기**로 공통 고려 사항을 기본 양식으로 바꿀 수 있습니다(커스텀 항목은 유지).
2. **검토**를 저장한 뒤, 검토자와 **다른 사용자**가 **검증**합니다.
3. 검증 담당자를 지정하면 해당 사용자의 대시보드에 검증 대기로 표시됩니다.

## 3.7 구성 정보(소스 관리)

![그림 3-7 구성 정보](images/user/03-07-source-management.png)

<!-- 캡처: /customers/:id/source-management. ① 엑셀로 내보내기 ② 수정 ③ 가상PC 이미지 관리 ④ 서버 접근 정보(민감 정보) -->

고객사의 클라이언트, 가상PC, 관리웹, 서버, 인사연동 구성을 관리합니다.

| 영역 | 주요 항목 |
|---|---|
| 클라이언트 정보 | 클라이언트 버전, 커스텀 정보 |
| 가상PC 이미지 관리 | 이미지별 OS(에디션·릴리즈), 드라이브 용량, 정품 인증, 설치 프로그램, 체크리스트 |
| 관리웹 정보 | 관리웹 버전, 세부 버전, 커스텀 정보 |
| 서버 접근 정보 | 관리웹 주소, 서버 주소·포트·계정·패스워드, 접근 여부 |
| 서버 구성 | 이중화 여부, 서버별 제조사·모델·호스트네임·OS·CPU·메모리·디스크·전원 |
| 인사연동 | 사용 여부, 인사DB 정보, 테이블·필드 매핑, 사용자·부서 연동 쿼리 |

**민감 정보 열람**

서버 접근 정보는 기본으로 가려져 있습니다. **클릭하여 보기**를 눌러야 표시되며, 열람 기록이 남습니다.

**엑셀 내보내기**

- **엑셀로 내보내기**: 구성 정보 전체
- **이미지 정보 엑셀**: 가상PC 이미지 정보만

### 3.7.1 구성 정보 수정

![그림 3-8 구성 정보 수정](images/user/03-08-source-management-edit.png)

<!-- 캡처: 수정 화면의 가상PC 이미지 영역. ① 이미지 정보 추가 ② 이미지 n/30개 ③ 체크리스트 -->

1. **수정**을 누르고 항목을 입력한 뒤 **저장**합니다.
2. 가상PC 이미지는 **이미지 정보 추가**로 최대 **30개**까지 등록할 수 있으며 최소 1개가 필요합니다.
3. 이미지별 필수 항목: 이름, OS, 에디션, 릴리즈, C 드라이브 용량. 정품 인증이 **미진행**이면 정품 인증 비고(사유)도 필수입니다.
4. D 드라이브 용량을 입력하면 D 드라이브 관련 체크리스트 항목이 활성화됩니다.

**이미지가 많을 때**

이미지가 5개를 넘으면 처음 5개만 표시되고, 아래의 **나머지 N개 펼치기**로 모두 볼 수 있습니다. 이미지를 추가하거나 저장 시 6번째 이후 이미지에 오류가 있으면 자동으로 펼쳐집니다.

> 다른 사람이 편집 중에 이미지를 재제작하면 저장이 거부됩니다. 입력한 내용은 화면에 남아 있으니 복사해 둔 뒤 새로고침하고 다시 입력하세요.

### 3.7.2 가상PC 체크리스트

이미지마다 설정 확인·구동 테스트 항목을 **검토**하고, 검토자와 다른 사용자가 **검증**합니다. 검증 담당자를 지정하면 해당 사용자의 대시보드에 검증 대기로 표시됩니다.

### 3.7.3 가상PC 이미지 재제작

![그림 3-9 재제작](images/user/03-09-rebuild.png)

<!-- 캡처: 이미지 카드의 재제작 버튼과 재제작 다이얼로그 -->

3. 등록하면 판 번호가 올라가고(`rev.2`, `rev.3` …), 이전 판은 **재제작 이력**으로 보관됩니다.

> 재제작하면 체크리스트의 검토·검증 결과와 비고가 모두 초기화되어 다시 검토·검증해야 합니다.

# 5. Q&A

**Q1. 로그인이 안 됩니다.**
아이디·패스워드를 확인하세요. 연속으로 여러 번 틀리면 계정이 일정 시간 잠길 수 있습니다. 잠금이 풀리지 않거나 비밀번호가 기억나지 않으면 관리자에게 **패스워드 초기화**를 요청하세요.

**Q2. 비밀번호를 초기화받았는데 무엇을 입력하나요?**
관리자가 안내한 초기 비밀번호로 로그인하면 비밀번호 변경 창이 나타납니다. 새 비밀번호로 변경한 뒤 다시 로그인하세요.

**Q3. "허용되지 않은 IP" 등으로 접속이 거부됩니다.**
IP 접근 제한이 켜져 있으면 등록된 IP에서만 로그인할 수 있습니다. 근무 위치(IP)가 바뀌었다면 관리자에게 허용 IP 변경을 요청하세요.

**Q4. 휴대폰을 바꿔 OTP 코드를 받을 수 없습니다.**
관리자에게 **OTP 등록 초기화**를 요청한 뒤, 다음 로그인 때 새 휴대폰으로 다시 등록하세요.

**Q5. 사용 중에 갑자기 로그아웃됐습니다.**
일정 시간 사용하지 않아 세션이 종료됐거나, 같은 계정으로 다른 곳에서 로그인한 경우입니다. 다시 로그인하세요.

**Q6. 점검서 업로드 시 점검 대상이 없다고 나옵니다.**
고객사 정보 수정 화면에서 **점검 대상 제품 추가**로 유형·제품명을 먼저 등록하세요.

**Q7. 점검서 파일이 업로드되지 않습니다.**
허용 형식(pdf, doc, docx, hwp, hwpx, ppt, pptx)인지, 파일 크기가 업로드 한도(기본 16MB)를 넘지 않는지 확인하세요. 바이러스가 탐지된 파일은 업로드가 거부됩니다.

**Q8. 잘못 올린 점검서를 지우고 싶습니다.**
점검서 삭제는 관리자만 할 수 있습니다. 관리자에게 요청하세요.

**Q9. 다른 사람이 작성한 지원 내역을 수정할 수 없습니다.**
지원 내역(진척 사항)은 작성자 본인과 관리자만 수정·삭제할 수 있습니다.

**Q10. 지원 로그의 "기존 기록(읽기 전용)"은 무엇인가요?**
지원 내역 기능 도입 전에 입력된 진척 사항입니다. 이후 진행 내용은 지원 내역으로 추가하세요.

**Q11. 가상PC 이미지를 더 추가할 수 없습니다.**
이미지는 고객사당 최대 30개까지 등록할 수 있습니다.

**Q12. 구성 정보 저장 시 "재제작" 관련 메시지가 나옵니다.**
편집 중에 다른 사용자가 이미지를 재제작한 경우입니다. 입력한 내용을 복사해 두고 새로고침한 뒤 다시 입력하세요.

**Q13. 체크리스트 검증 버튼이 눌리지 않습니다.**
검토를 먼저 저장해야 하며, 검토자 본인은 검증할 수 없습니다. 다른 사용자가 검증해야 합니다.

**Q14. 고객사 목록의 검색 조건이 사라졌습니다.**
검색어와 필터는 고객사 관리 화면을 벗어나면 초기화됩니다. 보던 페이지 번호는 유지됩니다.

**Q15. 대시보드에 담당 고객사가 없습니다.**
담당 엔지니어로 지정된 고객사가 없는 상태입니다. 관리자에게 담당 지정을 요청하세요.
