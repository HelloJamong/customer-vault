# 3. 계정 관리

## 3.1 계정 종류와 제한

| 계정 | 화면 | 최대 인원 | 허용 IP |
|---|---|---|---|
| 슈퍼관리자 | 계정관리 → 슈퍼관리자 | 3명 | 최대 2개 |
| 관리자 | 계정관리 → 관리자 | 10명 | 최대 2개 |
| 일반 사용자 | 계정관리 → 사용자 | 제한 없음 | 최대 1개 |

일반 사용자는 **소속**(기술팀, 영업팀, 개발팀)을 지정해야 합니다. 소속은 2차 인증 적용 대상 선택에 사용됩니다.

## 3.2 계정 추가

![그림 3-1 사용자 관리](images/admin/03-01-users.png)

<!-- 캡처: 계정관리 → 사용자 목록. ① 일반 사용자 추가 ② 상태 ③ 액션 메뉴 -->

1. **일반 사용자 추가**를 누릅니다. 관리자·슈퍼관리자 계정은 슈퍼관리자가 각 화면에서 추가합니다.
2. **계정**, **이름**, (일반 사용자는) **소속**을 입력합니다. 이메일, 설명, 허용 IP는 선택입니다.
3. **추가**를 누르면 시스템 설정의 **초기 패스워드**로 계정이 만들어집니다.
4. 사용자에게 계정과 초기 패스워드를 전달합니다. 사용자는 최초 로그인 시 비밀번호를 변경해야 합니다.

> 시스템 IP 접근 제한이 켜져 있으면 계정을 만들 때 허용 IP 입력이 필수입니다.

## 3.3 계정 관리 메뉴

![그림 3-2 액션 메뉴](images/admin/03-02-user-actions.png)

<!-- 캡처: 목록 행의 액션 메뉴(⋮) 펼친 상태 -->

| 메뉴 | 동작 |
|---|---|
| 수정 | 이름, 이메일, 소속, 설명, 허용 IP 변경. IP를 바꾸면 해당 사용자의 기존 세션이 종료됩니다. |
| 비활성화/활성화 | 로그인 차단·허용. 본인 계정은 비활성화할 수 없습니다. |
| 패스워드 초기화 | 초기 패스워드로 재설정. 사용자는 다음 로그인 시 비밀번호를 변경해야 합니다. |
| OTP 등록 초기화 | 2차 인증 등록 해제. 사용자는 다음 로그인 시 다시 등록합니다. |
| 삭제 | 계정 삭제. 본인 계정은 삭제할 수 없습니다. |

**계정 상태**: 정상, 비활성, 잠김(로그인 실패 횟수 초과)

> 일반 관리자는 **일반 사용자 계정만** 추가·관리할 수 있습니다. 관리자 계정의 추가, 허용 IP 변경, 패스워드·OTP 초기화, 비활성화, 삭제는 슈퍼관리자만 할 수 있습니다.

# 4. 업무 현황

## 4.1 점검 현황

![그림 4-1 점검 현황](images/admin/04-01-inspections.png)

<!-- 캡처: 업무 현황 → 점검 현황 목록과 '자세히 보기' 다이얼로그 -->

고객사별 마지막 점검일과 **누락된 점검서 수**를 확인합니다.

- **자세히 보기**: 정·부 담당자, 점검 대상별 누락된 점검 기간과 예상 점검서명
- 누락 계산은 고객사의 **계약 시작일**(최초 계약일)과 점검 주기를 기준으로 합니다. 계약을 갱신할 때 계약 시작일을 바꾸면 누락 판정이 달라지므로 **계약 종료일만** 변경하도록 안내하세요.

## 4.2 고객사 담당 현황

![그림 4-2 고객사 담당 현황](images/admin/04-02-assignments.png)

<!-- 캡처: 업무 현황 → 고객사 담당 현황 -->

기술팀 담당자별로 **정 고객사 수**, **부 고객사 수**를 확인합니다. **수정**으로 담당자별 비고(메모)를 남길 수 있습니다.

담당자 지정 자체는 각 고객사의 정보 수정 화면에서 **담당 엔지니어**, **부 엔지니어**, **담당 영업**으로 합니다.

# 5. 고객사·점검서 관리(관리자 전용 기능)

## 5.1 고객사 삭제

![그림 5-1 고객사 삭제](images/admin/05-01-customer-delete.png)

<!-- 캡처: 고객사 정보 수정 화면 하단 고객사 삭제와 확인 다이얼로그 -->

1. 고객사 정보 수정 화면에서 **고객사 삭제**를 누릅니다.
2. 확인 창에 **고객사명을 정확히** 입력하고 삭제합니다.

> 고객사를 삭제하면 해당 고객사의 점검서, 지원 목록, 회의록, 구성 정보 등 관련 데이터가 함께 삭제됩니다. 삭제 전 백업 여부를 확인하세요.

## 5.2 점검서 삭제

점검서 보기 화면에서 **삭제**를 누르고 확인합니다. 삭제한 점검서는 되돌릴 수 없습니다.

## 5.3 공지사항 작성

![그림 5-2 공지사항 작성](images/admin/05-02-notice-write.png)

<!-- 캡처: 공지사항 작성 다이얼로그 -->

1. **공지사항** → **공지사항 작성**을 누릅니다.
2. 제목과 내용을 입력하고 **작성**을 누릅니다.
3. 작성된 공지는 사용자 로그인 시 팝업으로 표시됩니다(사용자가 "다시 보지 않기"를 누르기 전까지).

목록의 메뉴에서 **수정**, **삭제**할 수 있습니다.

# 7. 시스템 설정 (슈퍼관리자)

![그림 7-1 시스템 설정](images/admin/07-01-settings.png)

<!-- 캡처: 시스템 설정 전체(여러 장으로 나눠 캡처) -->

설정을 바꾼 뒤 화면 아래의 **저장**을 눌러야 적용됩니다.

## 7.1 패스워드 정책

| 설정 | 설명 |
|---|---|
| 초기 패스워드 | 신규 계정 생성·패스워드 초기화 시 사용하는 기본 패스워드 |
| 패스워드 복잡성 | 최소 자릿수, 대문자·특수문자·숫자 필수 여부 |
| 패스워드 변경 주기 | 활성화 시 주기가 지나면 로그인할 때 변경을 강제 |

## 7.2 세션·로그인 보안

| 설정 | 설명 |
|---|---|
| 중복 로그인 방지 | 같은 계정으로 새로 로그인하면 기존 세션 종료 |
| 세션 타임아웃 | 미사용 시 자동 종료(분 단위, 최대 60분). 종료 1분 전 안내 팝업 |
| 로그인 실패 횟수 제한 | 최대 실패 횟수 초과 시 계정 잠금 시간 동안 잠금 |

## 7.3 2차 인증(OTP)

Authenticator 앱 기반 TOTP 인증으로, 폐쇄망에서도 사용할 수 있습니다.

1. **2차 인증 활성화**를 켭니다.
2. **적용 대상**을 선택합니다: 관리자(슈퍼/일반), 기술팀, 영업팀, 개발팀
3. 저장하면 적용 대상 사용자는 다음 로그인 때 OTP를 등록합니다. 관리자 본인이 대상이면 저장 후 다시 로그인해 등록합니다.

> OTP를 분실한 사용자는 계정 관리에서 **OTP 등록 초기화**를 해 주세요.

## 7.4 IP 접근 제한

활성화하면 모든 계정은 등록된 IP에서만 로그인할 수 있고, 세션도 로그인한 IP에 고정됩니다.

- 활성화할 때 기존 계정은 **최근 성공 로그인 IP**가 허용 목록에 자동 등록됩니다.
- 최근 성공 로그인 IP가 없는 활성 계정이 있으면 활성화가 거부됩니다. 먼저 계정 관리에서 해당 계정의 허용 IP를 등록하세요.

> 관리자 본인의 IP가 허용 목록에 있는지 확인한 뒤 활성화하세요.

## 7.5 JIRA 연동

**연동 기능 사용**을 켜고 JIRA 서버의 Base URL(예: `http://IP:포트`)을 입력합니다. 켜면 지원 로그에 JIRA 티켓 입력란과 티켓 링크가 표시됩니다.

## 7.6 데이터 백업 설정

| 설정 | 값 |
|---|---|
| 백업 기능 활성화 | 켜기/끄기 |
| 백업 주기 | 매일, 매주(요일), 매월(날짜) + 실행 시간 |
| 백업 항목 | DB, 점검서 파일 |
| 저장 경로 | 로컬(운영 서버 내 `backups/` 폴더) 또는 원격(SFTP) |
| 원격 서버 설정 | 서버 주소:포트, 계정, 패스워드 또는 키 파일 경로, 원격 백업 경로 |
| 보관 개수 | 최근 N개 유지(로컬 적용) |

원격 백업 경로 아래에 `db-backup/`, `doc-backup/` 폴더가 자동으로 만들어집니다.

# 8. 백업 관리 (슈퍼관리자)

![그림 8-1 백업 관리](images/admin/08-01-backup.png)

<!-- 캡처: 백업 관리 이력 목록. ① 즉시 백업 실행 ② 유형·대상·상태 ③ 다운로드 -->

- **즉시 백업 실행**: 설정과 관계없이 지금 백업을 실행합니다.
- **이력**: 유형(자동/수동), 대상(DB/점검서), 저장 경로(로컬/원격), 상태(성공/실패/실행 중), 크기, 시작·완료 시각
- **다운로드**: 백업 파일을 내려받습니다.

> 백업 파일은 암호화되어 있습니다. 복원하려면 서버의 `BACKUP_ENCRYPTION_KEY`가 필요하므로 이 값을 별도로 안전하게 보관하세요.

## 9.1 오프라인 업그레이드 요약

1. GitHub Release에서 `customer-vault-images-<버전>.tar.gz`, `docker-compose.yml`, `offline-upgrade.sh`를 받아 패키지 폴더에 둡니다.
2. 운영 서버에서 실행합니다.

   ```bash
   ./offline-upgrade.sh --app-dir <설치 경로> --package-dir <패키지 경로> --version <버전>
   ```

3. 스크립트가 자동으로 수행하는 작업
   - 암호화된 DB·파일 백업 생성(`../customer-vault-upgrade-backups/`)
   - 이미지 로드, `.env`의 `VERSION` 변경, DB 마이그레이션 적용
   - 백엔드·프록시 상태와 `/api/health` 확인. 실패하면 이전 버전 애플리케이션으로 자동 복귀(DB는 자동 복원하지 않음)

## 9.2 기존 지원 이력 변환 (1회성)

26.11.1 이전에 입력한 진척 사항(자유 텍스트)을 날짜별 지원 내역으로 나누는 도구입니다.

1. **계획 파일 생성**: 실행 직전에 운영 DB에서 지원 로그 id·수정 시각·제안 제목을 뽑아 계획 파일을 만듭니다. 추출 이후 수정된 로그는 변환에서 제외됩니다.
2. **점검 모드**(DB 변경 없음)로 결과를 확인합니다.

   ```bash
   docker compose exec -T backend node dist/scripts/convert-legacy-support-logs.js < support-log-conversion-plan.json
   ```

3. **DB 백업**을 만듭니다. 변환하면 원래 진척 사항 텍스트가 비워집니다.
4. **적용**합니다.

   ```bash
   docker compose exec -T backend node dist/scripts/convert-legacy-support-logs.js --apply < support-log-conversion-plan.json
   ```

5. 결과의 `skipped_warning`(날짜 오류·내용 없는 머리줄) 항목은 직접 확인합니다. 같은 계획 파일로 다시 실행해도 중복 생성되지 않습니다.

| 결과 | 의미 |
|---|---|
| converted | 지원 내역 생성(+ 빈 제목 채움) |
| title_only | 진척 사항 없이 제목만 채움 |
| nothing_to_do | 변경할 내용 없음 |
| skipped_not_found | DB에 해당 로그 없음 |
| skipped_changed | 계획 추출 이후 수정됨 |
| skipped_has_entries | 이미 지원 내역 있음 |
| skipped_warning | 자동 분리 불가, 직접 확인 필요 |

# 10. Q&A

**Q1. 사용자가 계정이 잠겼다고 합니다.**
로그인 실패 횟수 제한에 걸린 상태입니다. 설정된 잠금 시간이 지나면 풀립니다. 비밀번호를 잊은 경우 **패스워드 초기화**를 해 주세요.

**Q2. 패스워드를 초기화하면 사용자에게 무엇을 안내하나요?**
시스템 설정의 **초기 패스워드**로 로그인하고, 바로 새 비밀번호로 변경하도록 안내하세요.

**Q3. IP 접근 제한을 켰더니 접속이 안 되는 사용자가 있습니다.**
계정관리에서 해당 사용자의 **허용 IP**를 현재 접속 IP로 수정하세요. 관리자 본인도 막혔다면 허용된 IP의 PC에서 접속해 수정해야 합니다.

**Q4. IP 접근 제한 활성화가 거부됩니다.**
최근 성공 로그인 IP가 없는 활성 계정이 있기 때문입니다. 해당 계정의 허용 IP를 먼저 등록하거나, 사용하지 않는 계정이면 비활성화하세요.

**Q5. 관리자 계정을 더 만들 수 없습니다.**
관리자는 최대 10명, 슈퍼관리자는 최대 3명까지 만들 수 있습니다. 사용하지 않는 계정을 정리하세요.

**Q6. 일반 관리자인데 관리자 계정을 추가하거나 초기화할 수 없습니다.**
일반 관리자는 일반 사용자 계정만 관리할 수 있습니다. 관리자 계정의 추가, IP 변경, 패스워드·OTP 초기화, 비활성화, 삭제는 슈퍼관리자에게 요청하세요.

**Q7. 2차 인증을 켰는데 사용자가 OTP를 등록하지 못했습니다.**
적용 대상 사용자는 다음 로그인 때 등록 화면이 나타납니다. 휴대폰 분실 등으로 코드를 받을 수 없으면 **OTP 등록 초기화**를 해 주세요.

**Q8. 점검 현황의 누락 점검서 수가 이상합니다.**
고객사의 계약 시작일, 점검 주기, 점검 대상 제품을 확인하세요. 계약 시작일은 최초 계약일이어야 하며 갱신 시 바꾸지 않습니다.

**Q9. 사용자가 올린 점검서를 바로잡고 싶습니다.**
점검서 보기 화면에서 삭제한 뒤 사용자가 다시 업로드하도록 안내하세요.

**Q10. 백업이 실패합니다.**
백업 관리 이력에서 실패 시각을 확인하고, 원격(SFTP)이면 서버 주소·계정·키 파일 경로와 원격 경로 권한을, 로컬이면 서버 디스크 여유 공간을 확인하세요.

**Q11. 백업 파일을 복원하려면 무엇이 필요한가요?**
백업 파일과 해당 서버의 `BACKUP_ENCRYPTION_KEY`가 필요합니다. 키가 없으면 복원할 수 없습니다.

**Q12. 누가 서버 접속 정보(민감 정보)를 열람했는지 알 수 있나요?**
슈퍼관리자는 **시스템 이력**에서 민감 정보 열람 기록을 확인할 수 있습니다.

**Q13. 업그레이드 후 화면이 바뀌지 않았습니다.**
브라우저를 새로고침(Ctrl+F5)하세요. 계속 이전 화면이면 서버의 `.env` `VERSION`과 실행 중인 컨테이너 이미지 버전을 확인하세요.

**Q14. 업그레이드 후 이전 버전으로 되돌릴 수 있나요?**
애플리케이션은 이전 이미지로 되돌릴 수 있지만 DB 마이그레이션은 자동으로 되돌리지 않습니다. 업그레이드 전 백업으로 복원해야 하며, 신규 기능으로 저장한 데이터(예: 가상PC 이미지 11개 이상)는 이전 버전에서 저장이 거부될 수 있습니다.
